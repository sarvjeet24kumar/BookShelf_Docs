BookShelf API Documentation

Overview

Base URL: /api/v1/

All requests require Tenant-ID header (except SuperAdmin and public endpoints).

Authentication

Include access token in Authorization header:

Authorization: Bearer <access_token>

User Roles

Role Description
SUPER_ADMIN Platform-level access, manages tenants and admins
ADMIN Tenant administrator, manages users and books
USER Regular user, manages own library

1. Authentication Endpoints

1.1 Signup

Purpose: Register a new user for a tenant

Endpoint: POST /api/v1/auth/signup/

Header: Tenant-ID: <tenant_uuid>

Auth Required: No

Request Body:

{
  "username": "string",
  "email": "string",
  "password": "string",
  "password_confirm": "string",
  "first_name": "string ",
  "last_name": "string ",
  "phone_no": "string"
}

Success Response (200 OK):

{
  "detail": "Verification code sent to your email."
}

1.2 Verify Email

Purpose: Verify email with OTP after signup

Endpoint: POST /api/v1/auth/verify-email/

Header: Tenant-ID: <tenant_uuid>

Auth Required: No

Request Body:

{
  "email": "string",
  "username": "string ",
  "otp": "string (6 digits)"
}

Success Response (201 Created):

{
  "detail": "Email verified. Account activated successfully."
}

1.3 Resend OTP

Purpose: Resend verification OTP

Endpoint: POST /api/v1/auth/resend-otp/

Header: Tenant-ID: <tenant_uuid>

Auth Required: No

Request Body:

{
  "email": "string ",
  "username": "string"
}

Success Response (200 OK):

{
  "detail": "New verification code sent to your email."
}

1.4 Login

Purpose: Authenticate and receive login OTP

Endpoint: POST /api/v1/auth/login/

Header: Tenant-ID: <tenant_uuid> (optional for SuperAdmin)

Auth Required: No

Request Body:

{
  "email": "string ",
  "username": "string ",
  "password": "string"
}

Success Response (200 OK):

{
  "detail": "OTP sent to your email. Please verify to complete login."
}

1.5 Verify Login

Purpose: Complete login with OTP, receive JWT tokens

Endpoint: POST /api/v1/auth/verify-login/

Header: Tenant-ID: <tenant_uuid> (optional for SuperAdmin)

Auth Required: No

Request Body:

{
  "email": "string",
  "username": "string ",
  "otp": "string (6 digits)"
}

Success Response (200 OK):

{
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

1.6 Refresh Token

Purpose: Get new access token using refresh token

Endpoint: POST /api/v1/auth/refresh/

Auth Required: No

Request Body:

{
  "refresh": "string (JWT refresh token)"
}

Success Response (200 OK):

{
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

1.7 Logout

Purpose: Blacklist tokens and logout

Endpoint: POST /api/v1/auth/logout/

Auth Required: Yes

Request Body:

{
  "refresh": "string (JWT refresh token)"
}

Success Response (200 OK):

{
  "detail": "Logged out successfully"
}

1.8 Forgot Password

Purpose: Request password reset link

Endpoint: POST /api/v1/auth/forgot-password/

Auth Required: No

Request Body:

{
  "email": "string (or username)",
  "username": "string (or email)"
}

Success Response (200 OK):

{
  "detail": "If an account exists, a reset link has been sent to the registered email."
}

1.9 Reset Password

Purpose: Reset password using token

Endpoint: GET/POST /api/v1/auth/reset-password/

Auth Required: No

Query Parameter: token=<reset_token>

Request Body (POST):

{
  "token": "string",
  "password": "string",
  "confirm_password": "string"
}

Success: Renders HTML success page

1.10 Change Password

Purpose: Change password for authenticated user

Endpoint: POST /api/v1/auth/change-password/

Auth Required: Yes

Request Body:

{
  "current_password": "string",
  "new_password": "string",
  "confirm_password": "string"
}

Success Response (200 OK):

{
  "detail": "Password changed successfully. Please login with your new password."
}

2. User Management (Admin)

2.1 List Users

Purpose: Get paginated list of users

Endpoint: GET /api/v1/users/

Auth Required: Yes (SUPER_ADMIN, ADMIN)

Query Parameters: - page (optional): Page number - page_size (optional): Items per page

Success Response (200 OK):

{
  "count": 10,
  "next": "http://example.com/api/v1/users/?page=2",
  "previous": null,
  "results": [
    {
      "id": "uuid",
      "username": "string",
      "email": "string",
      "phone_no": "string",
      "role": "USER",
      "tenant": "uuid",
      "first_name": "string",
      "last_name": "string",
      "deleted_at": null,
      "created_at": "2026-01-29T12:00:00.000000Z"
    }
  ]
}

Notes: - SUPER_ADMIN sees all ADMIN users across tenants - ADMIN sees all USER role users in their tenant

2.2 Create User

Purpose: Create a new user (Admin creates users, SuperAdmin creates admins)

Endpoint: POST /api/v1/users/

Auth Required: Yes (SUPER_ADMIN, ADMIN)

Request Body:

{
  "username": "string",
  "email": "string",
  "password": "string",
  "phone_no": "string (optional)",
  "first_name": "string (optional)",
  "last_name": "string (optional)",
  "tenant": "uuid (required for SuperAdmin creating admin)"
}

Success Response (200 OK):

{
  "detail": "Verification code sent to your email."
}

2.3 Get User

Purpose: Get details of a specific user

Endpoint: GET /api/v1/users/{id}/

Auth Required: Yes

Path Parameters: - id (required): User UUID

Success Response (200 OK):

{
  "id": "uuid",
  "username": "string",
  "email": "string",
  "phone_no": "string",
  "role": "USER",
  "first_name": "string",
  "last_name": "string",
  "is_active": true,
  "deleted_at": null,
  "created_at": "2026-01-29T12:00:00.000000Z"
}

2.4 Update User

Purpose: Update user details

Endpoint: PATCH /api/v1/users/{id}/

Auth Required: Yes

Path Parameters: - id (required): User UUID

Request Body:

{
  "username": "string (optional)",
  "first_name": "string (optional)",
  "last_name": "string (optional)",
  "phone_no": "string (optional)",
  "is_active": "boolean (admin only)"
}

Success Response (200 OK):

{
  "id": "uuid",
  "username": "string",
  "email": "string",
  "phone_no": "string",
  "role": "USER",
  "first_name": "Updated Name",
  "last_name": "string",
  "is_active": true,
  "deleted_at": null,
  "created_at": "2026-01-29T12:00:00.000000Z"
}

Restrictions: - email and role are immutable - Regular users cannot update is_active or deleted_at - Admin cannot update other admins or themselves

2.5 Delete User

Purpose: Soft delete a user

Endpoint: DELETE /api/v1/users/{id}/

Auth Required: Yes

Path Parameters: - id (required): User UUID

Success Response (204 No Content):

(Empty response body)
